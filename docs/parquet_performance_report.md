## 核心优化技术

### 1. 统计信息剪枝
```
原理: 利用 Row Group min/max 统计
效果: 避免读取 90%+ 不相关数据 (大文件)
成本: 0 字节额外存储
```

### 2. 列式投影
```
原理: 只读取需要的列 (skip positions)
效果: 减少 50%+ I/O (对于 doc_ids only 查询)
成本: 0 字节额外存储
```

### 3. 批量处理
```
原理: 一次性读取，多次查找
效果: 摊销文件打开成本
成本: 临时内存 (查询期间)
```

### 4. 词项索引
```
原理: term → (row_group, offset) 映射
效果: O(1) 查找 (vs O(log n) Row Group scan)
成本: ~100% Parquet 大小
```

## 实际生产建议

### 小索引 (< 1MB)
```rust
// 完全加载到内存
let index = FullTextField::from_disk(&field, path)?;
let docs = index.term_query("rust")?;
```
**理由**: 加载成本可摊销，内存占用小

### 中等索引 (1MB - 100MB)
```rust
// 使用 Row Group 统计 (推荐)
let result = search_term(parquet_path, "rust")?;
```
**理由**: 零额外存储，性能优秀

### 大索引 (> 100MB) + 高频查询
```rust
// 使用 Term Index
let index = load_term_index("term_index.json")?;
let result = search_with_term_index(parquet_path, "rust", &index)?;
```
**理由**: O(1) 查找，索引常驻内存

### 只需 doc_ids 的查询
```rust
// 列式读取
let doc_ids = search_term_docids_only(parquet_path, "rust")?;
```
**理由**: 跳过 positions，减少 50% I/O

## 结论

### ✅ 最佳实践

1. **默认使用 Row Group 统计信息优化**
   - 零存储开销
   - 优秀的查询性能
   - 早期终止机制

2. **按需使用列式读取**
   - 只需要 doc_ids 时
   - 显著减少 I/O

3. **批量查询优化多词场景**
   - Boolean 查询
   - 聚合统计

4. **大索引高频场景考虑 Term Index**
   - 接受 ~100% 存储开销
   - 需要 O(1) 查找

### 🎯 核心优势

- **标准化**: 基于 Parquet 工业标准
- **自动化**: 压缩、编码、统计自动处理
- **灵活性**: 多种查询模式
- **可扩展**: 从 KB 到 GB 都适用
